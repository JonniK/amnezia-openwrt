# amnezia-openwrt — agent guide

AmneziaWG multi-tunnel failover VPN router for **OpenWrt 24.10.3** on a Xiaomi **AX3000T** (mediatek/filogic, aarch64). All runtime code is **POSIX sh / BusyBox ash**. Top constraint: **never break client internet** — every router action must be reversible and verified (WAN + DNS + tunnel handshake) before moving on.

## What it does

Routes LAN traffic selectively through AmneziaWG (`awg`) tunnels using **fwmark policy routing**, with automatic failover across multiple tunnels.

- **Classifier** (`/etc/nftables.d/30-amnezia-classify.nft`, prerouting/mangle) marks LAN traffic: sticky → `0x0a0000` (table `100`), pool → `0x0b0000` (table `101`); `MARK_MASK=0x0ff0000`. ip rules at pref `31000`/`31001` send marked traffic to those tables. The active classifier is **mode-generated** from a `@@LAN_IFNAME@@` template.
- **nft sets** decide routing: `amnezia_ru4` / `amnezia_ru_tld4` (Russia + `.ru` → direct), `amnezia_sticky4` (pin to sticky tunnel), `amnezia_force4` (the allowlist).
- **`routing_mode`** (`amnezia.config.routing_mode`): `tunnel-default` (foreign→tunnel, RU→direct — the normal mode) vs `direct-default` (everything direct, only `amnezia_force4`→tunnel). Switch via `amnezia-failover-ctl set-routing-mode`. In `tunnel-default` the force allowlist is **dormant** (classifier doesn't consult `force4`).
- **Direct-override** (`amnezia_direct4` set, `/etc/amnezia/direct-tunnel.list`): domains/IPs that must ALWAYS route direct (WAN), even when a broad force rule would tunnel them. The classifier consults `amnezia_direct4` **first** — before `sticky4`/`force4`, in both mode templates — and `return`s unmarked (→ WAN). Use case: a whole-AS force-source (e.g. `google` = AS15169, needed for RU-throttled YouTube/Meet) drags an unthrottled real-time host (`chat.google.com`) into the tunnel, degrading it; listing that host in `direct-tunnel.list` carves it back to direct while YouTube stays tunneled. Populated by `amnezia-force-load` (same subsystem as `force4`: IP/CIDR → set, domains → dnsmasq nftset directive `amnezia-direct.conf`; hash-gated single dnsmasq restart shared with force4; add-only). Kept hot by `amnezia-force-warm` (re-resolves both lists). CLI: `amnezia-failover-ctl direct-add|direct-remove|direct-list <domain>`. **Flush is set-scoped:** `amnezia-force-load --flush` flushes ONLY `force4`; `--flush-direct` flushes ONLY `amnezia_direct4` (never cross-flush — flushing `force4` strips fwmark from ESTABLISHED flows to RU-blocked hosts).
- **Failover daemon** `/usr/sbin/amnezia-failover` monitors tunnels, (re)installs ip rules + routing tables, and writes state JSON to `/var/run/amnezia-failover.json` (`routing_mode`, `force_pool`, `sources{}`, per-tunnel `exit_ip`/`exit_ip_age` for the UI). On each poll it spawns a detached flock-guarded background pass (`_refresh_exit_ips`) that probes each UP tunnel's public egress IP bound to its device (`curl --interface if!awgN`), cached with a 300 s TTL in `/tmp/amnezia-fo/exitip.<awgN>.ip|.ts`; probe results are read from cache on the poll path (no curl on the critical loop). Exit-IP cache is cleared on tunnel down→up transition and on tunnel removal (`amnezia-tunnel-ctl remove`).
- **Allowlist engine**: `amnezia-force-update` fetches enabled `force_source` UCI sections → `/etc/amnezia/force.d/<name>.list`; `amnezia-force-load` splits IP/CIDR → `amnezia_force4` nft set and domains → dnsmasq nftset directives. Two-trigger repopulation (volatile nft set): boot init (`START=96`) + firewall hotplug. Daily cron 03:15. `amnezia-force-warm` re-resolves manual force-tunnel domains through dnsmasq (127.0.0.1) every 2 min, keeping CDN IPs hot in `amnezia_force4` without any fw4 reload or state mutation.
- **RU routing**: `amnezia-ru-cidr` / `amnezia-ru-load` (weekly cron Sun 04:30).
- **Tunnel management**: `amnezia-tunnel-ctl add|remove|list-free` (paste `.conf` or Amnezia `vpn://`; the LuCI UI decodes `vpn://` client-side and passes only `.conf`). On `remove`, the exit-IP cache and debounce state for that slot are wiped so a re-added tunnel starts clean.
- **Pool pinning / make-default** (`amnezia.globals.force_pool`): `amnezia-failover-ctl make-default <awgN>` renumbers UCI metrics so the chosen enabled tunnel = 1 and the rest keep relative order (2, 3, …) and restarts the monitor. `force-pin <awgN>` sets `amnezia.globals.force_pool=<awgN>` and touches `/tmp/amnezia-fo/immediate` (triggers an immediate daemon reconcile without a restart). `force-unpin` deletes the option and touches `immediate`. Daemon `_best_pool` reads `globals.force_pool` each cycle: if set and UP → return it (auto-failover suspended); if set and DOWN → return empty (fail-closed, no silent switch to another tunnel). `force_pool` is emitted in the failover JSON. LuCI shows a warning banner when pinned; "Force pool through" select + Pin/Unpin buttons appear in the Failover section. Per-row **Make default** button is hidden when that tunnel is already the active pool or when `force_pool` is set.
- **Per-tunnel restart**: `amnezia-failover-ctl restart <awgN>` runs `ifdown <awgN>; sleep 1; ifup <awgN>`. Validates tunnel name; never touches other interfaces. LuCI per-row Restart button (with `uiConfirm` gate).
- **Master enable/disable** (`amnezia.config.master_enabled`, default `1`): `amnezia-failover-ctl master off` snapshots `dot_enabled` into transient UCI key `amnezia.config.dot_master_saved`, sets `master_enabled=0`, stops the failover daemon (which calls `routing_remove_rules`), flushes ip tables 100/101 and pref-30900 (DoT rule) explicitly, disables encrypted DNS, removes the state JSON, then verifies WAN + DNS. `master on` sets `master_enabled=1`, starts the daemon (reinstalls ip rules), re-enables DoT from the saved snapshot, deletes the saved key, and verifies. Verification failure is advisory only — never fails the verb. `failover.init start_service` calls `amz_master_enabled` (from `amnezia-common.sh`) and no-ops if it returns false, so OFF survives reboot. LuCI renders a master-state strip above the accordion; when OFF the accordion is dimmed (`.amnezia-master-off` CSS, `opacity:0.55;pointer-events:none`) but still readable.
- **Encrypted DNS (DoT/DoH)** (`amnezia.config.dot_enabled`, default `0`, opt-in): dnsmasq runs `noresolv`+`strict-order` over two loopback resolvers — stubby DoT on `127.0.0.1:5453` (egress via sticky tunnel, ip rule pref `30900` → table `100`) and https-dns-proxy DoH on `127.0.0.1:5454` (egress direct). A procd watchdog (`amnezia-dns-ctl watchdog`) gate-inserts a plaintext last-resort tier on N=3 consecutive encrypted failures and removes it after M=2 consecutive ok probes + 120s dwell — always BEHIND the encrypted listeners under `strict-order`. CLI: `amnezia-dns-ctl enable|disable|apply|set-provider|status|watchdog`. Providers: `quad9` (default), `adguard`, `dns0`, `mullvad`, `google`. Custom is backend-only via direct UCI (`dot_resolver`, `doh_resolver`, `doh_bootstrap`); the LuCI dropdown omits it. Requires `stubby` + `https-dns-proxy` packages (installer fetches them; feature degrades to plain provider DNS if absent). Default OFF = today's plaintext provider DNS, unchanged. **LuCI first-paint**: `main.load()` reads DoT status at index 10 (`fs.exec('/usr/bin/amnezia-dns-ctl',['status'])`); `dns.render()` parses this and populates the enable/disable checkbox and provider dropdown on first paint (no blank-row flash waiting for the first poll).
- **DNS-leak prevention** (`amnezia.config.dnsleak_enabled`, default `0`): `amnezia-dnsleak-ctl` installs three fw4 firewall rules — DNAT LAN port-53 to dnsmasq (intercept), REJECT LAN→WAN TCP 853 (block DoT), REJECT LAN→WAN TCP 443 to known DoH IPs (Cloudflare, Google, Quad9). Init is boot-enabled by the installer but the feature is **off by default**; activate with `amnezia-dnsleak-ctl enable`. A procd watchdog probes dnsmasq every 10 s and fails open (removes live nft rules while leaving UCI intact) if dnsmasq is unrecoverable, restoring them once healthy. CLI: `enable|disable|apply|status|failopen|failclosed|watchdog`.
- **Auto-tunnel domain auto-learning** (`amnezia.config.autotunnel_enabled`, default `0`, opt-in): `amnezia-autotunnel enable` writes a `log-queries` dnsmasq confdir snippet, restarts dnsmasq (health-check + auto-rollback on failure), and installs a per-minute cron (`amnezia-autotunnel auto`). The auto worker reads dnsmasq syslog, probes queried domains, and adds throttled/geo-blocked ones to the force-tunnel list. Added domains persist after `disable`. CLI: `enable|disable|status|auto|add|remove|probe`.

## Layout

**Device:** daemon `/usr/sbin/amnezia-failover`; vitals logger `/usr/sbin/amnezia-blackbox` (cron 1/min, appends uptime/temp/load/mem/transfer/dnsleak to `/etc/amnezia/blackbox.log`, size-capped at 3000 lines; active-pool-aware via `/var/run/amnezia-failover.json`); CLIs `/usr/bin/amnezia-{tunnel-ctl,force-load,force-update,force-warm,failover-ctl,status,ru-cidr}`; `amnezia-failover-ctl` verbs: `set-mode`, `set-sticky`, `set-weight`, `toggle`, `set-routing-mode`, `set-source`, `make-default <awgN>`, `force-pin <awgN>`, `force-unpin`, `restart <awgN>`, `master on|off`, `direct-add <domain>`, `direct-remove <domain>`, `direct-list`; libs `/usr/lib/amnezia/{amnezia-common,amnezia-routing,amnezia-tunnel-lib,amnezia-dns-lib}.sh`; inits `/etc/init.d/amnezia-{failover,ru-load,force-load}`; hotplugs `/etc/hotplug.d/firewall/99-amnezia-{ru-load,force-load}`; classifier active `/etc/nftables.d/30-amnezia-classify.nft`, templates `/usr/share/amnezia/nftables.d/`; config `/etc/config/amnezia` (`awgN` tunnels, `globals`, `config`, `force_source` sections); data `/etc/amnezia/` (`force.d/`, `force-tunnel.list`, `direct-tunnel.list`, `*.conf` — **private keys, never print/commit**, stamps) + `/etc/amnezia/dnsmasq.d/` (chunked nftset conf-dir); exit-IP cache `/tmp/amnezia-fo/exitip.<awgN>.ip|.ts` (probe cache, cleared on down→up / tunnel remove).

**`zapret-probe` 2nd arg**: optional pinned IPv4; when present curl uses `--resolve <domain>:443/<80>:<ip>` and `--max-redirs 0` (SSRF-safe). The existing LuCI single-arg path is unchanged.
**Device (DNS layer):** CLI `/usr/bin/amnezia-dns-ctl`; lib `/usr/lib/amnezia/amnezia-dns-lib.sh`; init `/etc/init.d/amnezia-dns` (START=97, USE_PROCD, runs watchdog as a respawned procd service); hotplug `/etc/hotplug.d/firewall/99-amnezia-dns` (re-runs `amnezia-dns-ctl apply` on firewall `reload` to re-assert the pref-30900 ip rule after fw4 flushes it).

**DNS UCI** (all under `amnezia.config`): `dot_enabled` (default `0`), `dns_provider` (`quad9`), `dot_resolver` / `doh_resolver` / `doh_bootstrap` (custom resolver overrides, empty), `dns_active_tier` (runtime state: `off`|`dot`|`doh`|`plaintext`), `dns_plain_ts` (watchdog plaintext-entry timestamp, persists across procd respawn). New package deps: `stubby` (DoT, listens `127.0.0.1:5453`), `https-dns-proxy` (DoH, listens `127.0.0.1:5454`). Lock: fd 8 on `/var/lock/amnezia-dnsmasq.lock` (DNS state machine); force-load uses fd 9 on the same path — distinct fd numbers but the same file so they serialize against each other.

**Master / pool-pin UCI**: `amnezia.config.master_enabled` (default `1`; `0` = fail-open bypass, persists across reboot); transient snapshot key `amnezia.config.dot_master_saved` (written by `master off`, deleted by `master on`). Pool-pin: `amnezia.globals.force_pool` (tunnel name or absent; set/deleted by `force-pin`/`force-unpin`). Exit-IP probe: `AMNEZIA_EXITIP_TTL` (env, default `300` s) and `AMNEZIA_IPECHO_URLS` (env, default `https://api.ipify.org https://ifconfig.co/ip`) — overridable in tests via env; production values are baked into `amnezia-common.sh`.

**LuCI app:** `openwrt/luci-app-amnezia/view/main.js` is the orchestration shell — it `require`s four section modules (`amnezia.section.{failover,routing,zapret,dns}`) and a shared util module (`amnezia.util`), `Object.assign`s their handler maps onto the view, and delegates polling via `Promise.all` of per-module `refresh()`. Feature logic lives in `openwrt/luci-app-amnezia/amnezia/util.js` (fmtDur/fmtAge/verdictColor/uiConfirm) and `amnezia/section/{failover,routing,zapret,dns}.js`. On device the modules land at `/www/luci-static/resources/amnezia/` (sibling of `resources/view/amnezia/`). All four delivery surfaces ship them: `dev/sync-to-packages.sh`, `openwrt/install-luci-app-amnezia.sh`, `install.sh`, and `dev/deploy-openwrt-safe.sh`. Presentation: a **master-state strip** (`#amz-master-strip`) above the accordion shows current master state with a Turn ON/OFF button (`handleMasterToggle`); below it a two-level native-`<details>` accordion (`#amz-accordion`): three status families open by default (Tunnels & Failover, Routing & Allowlist, Encrypted DNS); the **DPI bypass (zapret)** family and all action sub-sections (`amnezia-action`) collapsed. When master is OFF, `#amz-accordion` gets class `amnezia-master-off` (`opacity:0.55;pointer-events:none`). `main.load()` data bundle: index 10 = `fs.exec('/usr/bin/amnezia-dns-ctl',['status'])` (parsed by `dns.render()` for first-paint DoT toggle); index 11 = `fs.exec('/sbin/uci',['-q','get','amnezia.config.master_enabled'])` (parsed by `main.render()` for master strip). Named change handlers (all follow `ctlThenRefresh` shape — exec → notify → repaint, no unhandled rejection): `handleSetMode`, `handleSetSticky`, `handleDotToggle`, `handleDotProvider`, `handleMakeDefault`, `handleTunnelRestart`, `handleForcePin`, `handleForceUnpin`, `handleMasterToggle`. JS gate: `test/lib/luci-harness.js` stubs LuCI globals, loads the full require graph, executes every module `render()` + `main.render()`, invokes every named handler under succeeding and rejecting fs stubs, and self-tests that no action panel carries `open` and that all handlers resolve (never reject) — run by `test/unit/luci-js.bats`.

**Repo:** `openwrt/` is the source of truth; `dev/sync-to-packages.sh` mirrors it into `packages/` (the `.ipk` tree) — **keep `openwrt/ ↔ packages/` in sync** (CI checks it). Delivery is two paths: imperative `openwrt/install-amnezia-pbr.sh` (`--first-install` / `--migrate`, postinst-style) and the `.ipk`. Tests: `test/unit/*.bats` + `test/stubs/`. VM harness: `dev/vm/` (QEMU OpenWrt; `test-all.sh` = migrate / first-install / tunnel-mgmt scenarios). Router ops: `dev/{openwrt-backup,openwrt-restore,openwrt-emergency-internet,deploy-cutover,rollback-multitunnel}.sh`. SSH alias **`openWRT`** → `192.168.1.1:2323` (dev scripts default `SSH_HOST=router`, so pass `SSH_HOST=openWRT`).

## Hard-won rules

These come from bugs that passed the VM + unit tests and only surfaced on the live router. Root theme: **simulation must match real OpenWrt, or real bugs hide.**

### UCI: read option values with `uci -q get`, never `uci show | grep | sed`
Real `uci show` **quotes** option values (`amnezia.x.enabled='1'`) and renders lists on **one line** (`firewall.vpn.network='a' 'b'`). grep|sed on a value yields quoted junk (`'1' != 1`); counting list members by lines always returns 1. Both shipped real bugs: force-update read every source as disabled (fetched nothing); tunnel-ctl `_fwnet_count` always returned 1 → `remove` was a silent no-op. Use `uci -q get <path>` for values; for list membership iterate `uci -q get` words or use `uci del_list`/`add_list`. Only the unquoted **type** line (`x=force_source`) is safe to grep.

### Test stubs MUST mirror real tool output — a green stubbed/VM run is not proof
The bats `uci` stub emitted unquoted values + multi-line lists, so 240 tests **and** the VM passed while two bugs reached the live router. Stub `uci`/`dnsmasq`/`nft` in the exact real format. When a VM gate can't truly measure something (the VM's dnsmasq never served queries, so DNS-down was left "advisory"), that blind spot is exactly where a live-only bug hides — verify on real hardware before declaring done.

### dnsmasq config lines cap ~1024 bytes — chunk large domain sets into a conf-dir
A UCI `config ipset` section renders **all** its domains into one `nftset=/d1/d2/.../inet#fw4#set` line. >~1000 domains overflows dnsmasq's config-line buffer → `bad option` → dnsmasq won't start → **DNS outage** (hit live: 1185 itdoginfo domains = 16KB line). For large sets, write byte-chunked `nftset=` lines (≤~900B each) into a dnsmasq conf-dir wired via `uci dhcp.@dnsmasq[0].confdir`, not a UCI config-ipset section. Validate with `dnsmasq --test -C <file>`.

### nftables.d fragments: validate with `fw4 check`, not `nft -c -f`
`/etc/nftables.d/*.nft` are fw4 **includes** (valid only inside `table inet fw4 {...}`); standalone `nft -c -f` reports false syntax errors. Use `fw4 check` (assembled ruleset) before `fw4 reload`. The classifier active file is the `@@LAN_IFNAME@@` template substituted (templates in `/usr/share/amnezia/nftables.d/`, active in `/etc/nftables.d/`) — never drop a second classifier fragment into `/etc/nftables.d/` (duplicate `chain amnezia_classify` breaks reload). `fw4 reload` can drop SSH → run it backgrounded: `( sleep 1 && fw4 reload ) &`.

### Encrypted-DNS: commit tier state INSIDE the fd-8 lock, and always write encrypted listeners before plaintext
Two invariants that the watchdog and `cmd_apply` must maintain:

1. **Tier commit inside the lock.** `_enter_plain` and `_exit_plain` both hold the dnsmasq fd-8 lock across the full sequence: add/remove server entries → `dns_dnsmasq_reload` → commit `dns_active_tier` to UCI. The tier commit happens only after the reload succeeds, and only while the lock is held. If you move the tier commit outside the lock (or before the reload), `cmd_apply` can observe a `dns_active_tier=plaintext` window where dnsmasq hasn't yet restarted with the plaintext server, or keep a stale `plaintext` tier after a failed `_exit_plain`. Burned in review cycle 3: `_set_tier` was outside `_exit_plain`'s lock scope.

2. **Encrypted listeners must be FIRST in the dnsmasq server list.** dnsmasq `strict-order` tries servers in the order they appear in the config. `cmd_apply` explicitly calls `dns_dnsmasq_del_plain` before `dns_dnsmasq_encrypted` to strip any plaintext entries from ahead of the encrypted listeners, then re-appends plaintext after them when the watchdog has engaged the fallback tier. If a plaintext server ends up first in the list (e.g. from a previous watchdog entry that wasn't cleaned up), `strict-order` sends every query to it first, bypassing DoT/DoH entirely. Burned in review cycle 2.

### Live-router updates: apply the delta surgically, don't re-run the postinst installer
`install-amnezia-pbr.sh` is postinst-style — it assumes the `.ipk` already placed libs (`/usr/lib/amnezia/*.sh`) and the classifier. A manually-cutover router matches no install scenario; re-running the installer skips/half-applies. Update such a router by placing the specific changed files + wiring, verifying WAN/DNS/handshake after each step, snapshotting each replaced file first. SSH is LAN-side (`192.168.1.1:2323`) so it survives routing/tunnel breakage — it's the recovery channel; keep `dev/openwrt-emergency-internet.sh` ready and take a full backup (`dev/openwrt-backup.sh`) first.

**LuCI static JS is browser-cached — verify in a private window.** After deploying new `/www/luci-static/resources/...` JS, the browser serves the **cached** old modules; a normal refresh, and often even a hard refresh (`Cmd+Shift+R`), won't reload `require`-loaded section modules. Confirm the new UI in a **private/incognito window** or with DevTools → Network → "Disable cache". A partially-cached state (e.g. new `failover.js` but stale `main.js`) produces confusing half-broken panels that look like real bugs. (`rpcd restart` doesn't help — it's a server-side cache; the stale copy is in the browser.)

### LuCI `createHandlerFn` passes the event LAST — `fn(...extraArgs, event)`
`ui.createHandlerFn(ctx, 'handleX', a, b)` returns `L.bind(wrapper, ctx, a, b)`; when the DOM fires it the handler is invoked as `handleX(a, b, event)` — **extra args first, event last** (verified in the device's `ui.js`). So a handler wired with an extra arg MUST be declared `function(extraArg, ev)`, NOT `function(ev, extraArg)`. Getting it backwards puts the *event object* where the code expects the tunnel/domain name → it gets sent to the backend `fs.exec` → the click silently does nothing (no console error, since `createHandlerFn` still attaches a listener). This blanked **every** extra-arg button (toggle/remove/make-default/restart, master, source-toggle, probe) and went unnoticed from the PR #5 modular refactor until a live click-test. Handlers wired with NO extra arg are `function(ev)` and read `ev.target` (correct, event is the only arg). A handler wired BOTH ways (e.g. `handleProbe`) must be arity-robust (guard: `typeof first !== 'string'`).

### The offline LuCI harness must REPLICATE LuCI conventions, not assume them
`test/lib/luci-harness.js` is only as good as its fidelity to real LuCI. Two bugs shipped because the harness encoded the *same* wrong assumption as the code: (1) it called handlers as `(ev, extraArg)` — the buggy order — so the arg-order bug "passed"; (2) `documentStub.getElementById` returned a fake node, hiding that a render-time `getElementById` is `null` on the real router (a microtask paint races LuCI's DOM insertion → blank panel). Fixes, now in the harness: a `createHandlerFn` stub that binds extra-args-first / event-last exactly like LuCI, an `fs.exec` spy asserting **no event object leaks in as a backend arg**, and a render-tree walk asserting paint-on-render elements (e.g. the master strip) are populated. Rule: **paint synchronously in the returned render tree; use `getElementById` only in `refresh()`/click handlers** (DOM exists then). And remember: offline gates can't replace a live click-test for event wiring — the device smoke-test is the real gate.

### DoT: `enable` the stubby/https-dns-proxy services, and verify with `getdns_query` (not BusyBox nslookup)
Two bugs made `amnezia-dns-ctl enable` always auto-revert (DoT never worked live — VM blind spot): (1) the stubby/https-dns-proxy inits' `start_service` opens its procd instance **only when the service is `enabled`**, so a bare `restart` on a not-enabled service is a silent no-op (no listener on 5453/5454) — `dns_render_stubby`/`dns_render_doh` must `enable` before `restart`. (2) `_verify_encrypted` probed `nslookup -timeout=3 openwrt.org 127.0.0.1#5453`, but BusyBox `nslookup` rejects `host#port` (`bad address`) and has no `-timeout` — so the probe ALWAYS failed regardless of DoT health. Use `getdns_query -t <ms> -s @<ip>:<port> <host> A` (port-capable, ships with the getdns/stubby package; success = `GETDNS_RESPSTATUS_GOOD`); keep nslookup only as a port-53 fallback.

### Auto-learner undo: kill the cached verdict, and verify after the next cycle
`amnezia-autotunnel remove <domain>` does NOT stick while `/tmp/amnezia-autotunnel/verdicts` still holds a `throttled` entry for it — the per-minute auto worker re-adds from CACHE without re-probing (hit live 2026-07-06: removed Apple App Store search backends reappeared in ~1 min; their real LBs are `tunnel-down` through the tunnel, so the forced entry was itself the outage). Full undo = list entry + evict its IPs from `amnezia_force4` + delete its verdict-cache lines + an `autotunnel-exclude.list` entry if it must never return. And verify any change that a reconcile loop can contradict AFTER that loop's next cycle (≥2 min here) — an immediate "not-in-set ✓" proves nothing.
