# amnezia-openwrt — agent guide

AmneziaWG multi-tunnel failover VPN router for **OpenWrt 24.10.3** on a Xiaomi **AX3000T** (mediatek/filogic, aarch64). All runtime code is **POSIX sh / BusyBox ash**. Top constraint: **never break client internet** — every router action must be reversible and verified (WAN + DNS + tunnel handshake) before moving on.

## What it does

Routes LAN traffic selectively through AmneziaWG (`awg`) tunnels using **fwmark policy routing**, with automatic failover across multiple tunnels.

- **Classifier** (`/etc/nftables.d/30-amnezia-classify.nft`, prerouting/mangle) marks LAN traffic: sticky → `0x0a0000` (table `100`), pool → `0x0b0000` (table `101`); `MARK_MASK=0x0ff0000`. ip rules at pref `31000`/`31001` send marked traffic to those tables. The active classifier is **mode-generated** from a `@@LAN_IFNAME@@` template.
- **nft sets** decide routing: `amnezia_ru4` / `amnezia_ru_tld4` (Russia + `.ru` → direct), `amnezia_sticky4` (pin to sticky tunnel), `amnezia_force4` (the allowlist).
- **`routing_mode`** (`amnezia.config.routing_mode`): `tunnel-default` (foreign→tunnel, RU→direct — the normal mode) vs `direct-default` (everything direct, only `amnezia_force4`→tunnel). Switch via `amnezia-failover-ctl set-routing-mode`. In `tunnel-default` the force allowlist is **dormant** (classifier doesn't consult `force4`).
- **Failover daemon** `/usr/sbin/amnezia-failover` monitors tunnels, (re)installs ip rules + routing tables, and writes state JSON to `/var/run/amnezia-failover.json` (`routing_mode` + `sources{}` for the UI).
- **Allowlist engine**: `amnezia-force-update` fetches enabled `force_source` UCI sections → `/etc/amnezia/force.d/<name>.list`; `amnezia-force-load` splits IP/CIDR → `amnezia_force4` nft set and domains → dnsmasq nftset directives. Two-trigger repopulation (volatile nft set): boot init (`START=96`) + firewall hotplug. Daily cron 03:15. `amnezia-force-load` also applies a guarded suffix-aware global exclusion from `/etc/amnezia/autolearn/deny.list` (vetoed domains; a missing/empty deny.list is a no-op and can never blank force4).
- **Auto-learning** (`amnezia-autolearn`, `direct-default` mode only, **opt-in, default OFF**): a cron pass that harvests visited domains from the dnsmasq query log, probes each candidate via `zapret-probe` with a pinned IP (SSRF-safe `--resolve`, no redirects), and auto-adds confirmed-blocked domains to `/etc/amnezia/force.d/auto.list` → `amnezia_force4`. Thresholds: geoblock confirmed at 2 verdicts, DPI at 3. Per-client fairness cap; domain eligible only if ≥2 distinct client IPs resolved it. LRU-eviction at `autolearn_max_entries` cap. Revalidation every `autolearn_revalidate_days` days drops domains that now pass direct. Probe egresses DIRECT (router-origin, bypasses prerouting classifier) so revalidation-drop is sound. Guarded by: `routing_mode=direct-default`, `autolearn_enabled=1`, tunnel-health state file fresh + `all_down:false`.
- **RU routing**: `amnezia-ru-cidr` / `amnezia-ru-load` (weekly cron Sun 04:30).
- **Tunnel management**: `amnezia-tunnel-ctl add|remove|list-free` (paste `.conf` or Amnezia `vpn://`; the LuCI UI decodes `vpn://` client-side and passes only `.conf`).
- **Encrypted DNS (DoT/DoH)** (`amnezia.config.dot_enabled`, default `0`, opt-in): dnsmasq runs `noresolv`+`strict-order` over two loopback resolvers — stubby DoT on `127.0.0.1:5453` (egress via sticky tunnel, ip rule pref `30900` → table `100`) and https-dns-proxy DoH on `127.0.0.1:5454` (egress direct). A procd watchdog (`amnezia-dns-ctl watchdog`) gate-inserts a plaintext last-resort tier on N=3 consecutive encrypted failures and removes it after M=2 consecutive ok probes + 120s dwell — always BEHIND the encrypted listeners under `strict-order`. CLI: `amnezia-dns-ctl enable|disable|apply|set-provider|status|watchdog`. Providers: `quad9` (default), `adguard`, `dns0`, `mullvad`, `google`. Custom is backend-only via direct UCI (`dot_resolver`, `doh_resolver`, `doh_bootstrap`); the LuCI dropdown omits it. Requires `stubby` + `https-dns-proxy` packages (installer fetches them; feature degrades to plain provider DNS if absent). Default OFF = today's plaintext provider DNS, unchanged.

## Layout

**Device:** daemon `/usr/sbin/amnezia-failover`; CLIs `/usr/bin/amnezia-{tunnel-ctl,force-load,force-update,failover-ctl,status,ru-cidr}`; autolearn CLI `/usr/bin/amnezia-autolearn-ctl` (`status|list|veto|promote|purge|set-enabled`); autolearn pass `/usr/sbin/amnezia-autolearn`; libs `/usr/lib/amnezia/{amnezia-common,amnezia-routing,amnezia-tunnel-lib,amnezia-autolearn-lib}.sh`; inits `/etc/init.d/amnezia-{failover,ru-load,force-load,autolearn}`; hotplugs `/etc/hotplug.d/firewall/99-amnezia-{ru-load,force-load}`; classifier active `/etc/nftables.d/30-amnezia-classify.nft`, templates `/usr/share/amnezia/nftables.d/`; config `/etc/config/amnezia` (`awgN` tunnels, `globals`, `config`, `force_source` sections); data `/etc/amnezia/` (`force.d/`, `force-tunnel.list`, `*.conf` — **private keys, never print/commit**, stamps) + `/etc/amnezia/dnsmasq.d/` (chunked nftset conf-dir) + `/etc/amnezia/autolearn/` (`candidates.tsv` 7-col TSV, `deny.list`, `autolearn.json` UI state, offset file `.dnsmasq-log.offset`); tmpfs DNS log `/tmp/dnsmasq-queries.log` (present only while autolearn is enabled).

**Autolearn UCI** (all under `amnezia.config`): `autolearn_enabled` (default `0`), `autolearn_interval_min` (`30`), `autolearn_max_probes` (`20`), `autolearn_max_per_client` (`5`), `autolearn_revalidate_days` (`14`), `autolearn_max_entries` (`500`), `autolearn_candidate_retention_days` (`30`). Enable/disable via `amnezia-autolearn-ctl set-enabled 0|1` (wires/unwires dnsmasq query logging + cron). The init's `disable()` guards against clobbering a pre-existing user dnsmasq logfacility — it only removes options it set.

**`zapret-probe` 2nd arg**: optional pinned IPv4; when present curl uses `--resolve <domain>:443/<80>:<ip>` and `--max-redirs 0` (SSRF-safe). Used by autolearn; the existing LuCI single-arg path is unchanged.
**Device:** daemon `/usr/sbin/amnezia-failover`; CLIs `/usr/bin/amnezia-{tunnel-ctl,force-load,force-update,failover-ctl,status,ru-cidr,amnezia-dns-ctl}`; libs `/usr/lib/amnezia/{amnezia-common,amnezia-routing,amnezia-tunnel-lib,amnezia-dns-lib}.sh`; inits `/etc/init.d/amnezia-{failover,ru-load,force-load,dns}` (amnezia-dns: START=97, USE_PROCD, runs watchdog as a respawned procd service); hotplugs `/etc/hotplug.d/firewall/99-amnezia-{ru-load,force-load,dns}` (dns hotplug re-runs `amnezia-dns-ctl apply` on firewall `reload` to re-assert the pref-30900 ip rule after fw4 flushes it); classifier active `/etc/nftables.d/30-amnezia-classify.nft`, templates `/usr/share/amnezia/nftables.d/`; config `/etc/config/amnezia` (`awgN` tunnels, `globals`, `config`, `force_source` sections); data `/etc/amnezia/` (`force.d/`, `force-tunnel.list`, `*.conf` — **private keys, never print/commit**, stamps) + `/etc/amnezia/dnsmasq.d/` (chunked nftset conf-dir).

**DNS UCI** (all under `amnezia.config`): `dot_enabled` (default `0`), `dns_provider` (`quad9`), `dot_resolver` / `doh_resolver` / `doh_bootstrap` (custom resolver overrides, empty), `dns_active_tier` (runtime state: `off`|`dot`|`doh`|`plaintext`), `dns_plain_ts` (watchdog plaintext-entry timestamp, persists across procd respawn). New package deps: `stubby` (DoT, listens `127.0.0.1:5453`), `https-dns-proxy` (DoH, listens `127.0.0.1:5454`). Lock: fd 8 on `/var/lock/amnezia-dnsmasq.lock` (DNS state machine); force-load uses fd 9 on the same path — distinct fd numbers but the same file so they serialize against each other.

**LuCI app:** `openwrt/luci-app-amnezia/view/main.js` is a ~129-line orchestration shell — it `'require's five section modules (`amnezia.section.{failover,routing,zapret,dns,autolearn}`) and a shared util module (`amnezia.util`), `Object.assign`s their handler maps onto the view, and delegates polling via `Promise.all` of per-module `refresh()`. Feature logic lives in `openwrt/luci-app-amnezia/amnezia/util.js` (fmtDur/fmtAge/verdictColor/uiConfirm) and `amnezia/section/{failover,routing,zapret,dns,autolearn}.js`. On device the modules land at `/www/luci-static/resources/amnezia/` (sibling of `resources/view/amnezia/`). All four delivery surfaces ship them: `dev/sync-to-packages.sh`, `openwrt/install-luci-app-amnezia.sh`, `install.sh`, and `dev/deploy-openwrt-safe.sh`. Presentation is a two-level native-`<details>` accordion: four status families open by default (Tunnels & Failover, Routing & Allowlist, Encrypted DNS, Auto-learning); the **DPI bypass (zapret)** family and all action sub-sections (`amnezia-action`) collapsed. JS gate: `test/lib/luci-harness.js` stubs LuCI globals, loads the full require graph, executes every module `render()` + `main.render()`, and self-tests that no action panel carries `open` — run by `test/unit/luci-js.bats`.

**Repo:** `openwrt/` is the source of truth; `dev/sync-to-packages.sh` mirrors it into `packages/` (the `.ipk` tree) — **keep `openwrt/ ↔ packages/` in sync** (CI checks it). Delivery is two paths: imperative `openwrt/install-amnezia-pbr.sh` (`--first-install` / `--migrate`, postinst-style) and the `.ipk`. Tests: `test/unit/*.bats` + `test/stubs/`. VM harness: `dev/vm/` (QEMU OpenWrt; `test-all.sh` = migrate / first-install / tunnel-mgmt scenarios). Router ops: `dev/{openwrt-backup,openwrt-restore,openwrt-emergency-internet,deploy-cutover,rollback-multitunnel}.sh`. SSH alias **`openWRT`** → `192.168.1.1:2323` (dev scripts default `SSH_HOST=router`, so pass `SSH_HOST=openWRT`).

## Hard-won rules

These come from bugs that passed the VM + unit tests and only surfaced on the live router. Root theme: **simulation must match real OpenWrt, or real bugs hide.**

### UCI: read option values with `uci -q get`, never `uci show | grep | sed`
Real `uci show` **quotes** option values (`amnezia.x.enabled='1'`) and renders lists on **one line** (`firewall.vpn.network='a' 'b'`). grep|sed on a value yields quoted junk (`'1' != 1`); counting list members by lines always returns 1. Both shipped real bugs: force-update read every source as disabled (fetched nothing); tunnel-ctl `_fwnet_count` always returned 1 → `remove` was a silent no-op. Use `uci -q get <path>` for values; for list membership iterate `uci -q get` words or use `uci del_list`/`add_list`. Only the unquoted **type** line (`x=force_source`) is safe to grep.

### Test stubs MUST mirror real tool output — a green stubbed/VM run is not proof
The bats `uci` stub emitted unquoted values + multi-line lists, so 240 tests **and** the VM passed while two bugs reached the live router. Stub `uci`/`dnsmasq`/`nft` in the exact real format. When a VM gate can't truly measure something (the VM's dnsmasq never served queries, so DNS-down was left "advisory"), that blind spot is exactly where a live-only bug hides — verify on real hardware before declaring done.

### dnsmasq config lines cap ~1024 bytes — chunk large domain sets into a conf-dir
A UCI `config ipset` section renders **all** its domains into one `nftset=/d1/d2/.../inet#fw4#set` line. >~1000 domains overflows dnsmasq's config-line buffer → `bad option` → dnsmasq won't start → **DNS outage** (hit live: 1185 itdoginfo domains = 16KB line). For large sets, write byte-chunked `nftset=` lines (≤~900B each) into a dnsmasq conf-dir wired via `uci dhcp.@dnsmasq[0].confdir`, not a UCI config-ipset section. Validate with `dnsmasq --test -C <file>`.

### nftables.d fragments: validate with `fw4 check`, not `nft -c -f`
`/etc/nftables.d/*.nft` are fw4 **includes** (valid only inside `table inet fw4 {...}`); standalone `nft -c -f` reports false syntax errors. Use `fw4 check` (assembled ruleset) before `fw4 reload`. The classifier active file is the `@@LAN_IFNAME@@` template substituted (templates in `/usr/share/amnezia/nftables.d/`, active in `/etc/nftables.d/`) — never drop a second classifier fragment into `/etc/nftables.d/` (duplicate `chain amnezia_classify` breaks reload). `fw4 reload` can drop SSH → run it backgrounded: `( sleep 1 && fw4 reload ) &`.

### Encrypted-DNS: commit tier state INSIDE the fd-8 lock, and always write encrypted listeners before plaintext
Two invariants that the watchdog and `cmd_apply` must maintain:

1. **Tier commit inside the lock.** `_enter_plain` and `_exit_plain` both hold the dnsmasq fd-8 lock across the full sequence: add/remove server entries → `dns_dnsmasq_reload` → commit `dns_active_tier` to UCI. The tier commit happens only after the reload succeeds, and only while the lock is held. If you move the tier commit outside the lock (or before the reload), `cmd_apply` can observe a `dns_active_tier=plaintext` window where dnsmasq hasn't yet restarted with the plaintext server, or keep a stale `plaintext` tier after a failed `_exit_plain`. Burned in review cycle 3: `_set_tier` was outside `_exit_plain`'s lock scope.

2. **Encrypted listeners must be FIRST in the dnsmasq server list.** dnsmasq `strict-order` tries servers in the order they appear in the config. `cmd_apply` explicitly calls `dns_dnsmasq_del_plain` before `dns_dnsmasq_encrypted` to strip any plaintext entries from ahead of the encrypted listeners, then re-appends plaintext after them when the watchdog has engaged the fallback tier. If a plaintext server ends up first in the list (e.g. from a previous watchdog entry that wasn't cleaned up), `strict-order` sends every query to it first, bypassing DoT/DoH entirely. Burned in review cycle 2.

### Live-router updates: apply the delta surgically, don't re-run the postinst installer
`install-amnezia-pbr.sh` is postinst-style — it assumes the `.ipk` already placed libs (`/usr/lib/amnezia/*.sh`) and the classifier. A manually-cutover router matches no install scenario; re-running the installer skips/half-applies. Update such a router by placing the specific changed files + wiring, verifying WAN/DNS/handshake after each step, snapshotting each replaced file first. SSH is LAN-side (`192.168.1.1:2323`) so it survives routing/tunnel breakage — it's the recovery channel; keep `dev/openwrt-emergency-internet.sh` ready and take a full backup (`dev/openwrt-backup.sh`) first.
